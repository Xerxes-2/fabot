# Only Work bodies draw from the upgrade buffer

> **Amended by #216 R5** on the buffer's **capacity** and not on this gate: the store that admits only Work bodies now divides twice, once per [[body class]] — the generalists by a [[worker unit]]'s load and the [[standing body]] row by its own fifty — because two rows drink here and a single number made them compete for a divisor derived from one of them (#196, the question ADR 0046's Consequences left to the tracker). The Work-part gate itself is exactly as decided.

Live observation of W12S28 (RCL3, tick ~65600, spawn/extensions/tower all full) caught both haulers in a one-tick loop on the controller container: `withdraw:can-ctrl (task-gone)` → `refill:can-ctrl (only-candidate)` → `refill (inapplicable)` → `withdraw (travel-cost)`, forever. Neither ever delivered; meanwhile one source container held 6 energy and the other was backing up. The loop is structural, not a tuning miss: the Planner pools the controller container as a Withdraw while it is stocked *and* as a Refill while it has room (ADR 0012), so a filled hauler whose every other sink is full has exactly one Refill target — the container it just emptied — and once it dumps there, Withdraw is stocked again, sits at the feeding tier, and prices at travel cost 0. We decided **Withdraw on a controller container is inapplicable to a body with no Work part**. The gate is part arithmetic in the ADR 0016 family, read from what the creep is made of, never from a name or a birth row: a carrier with no Work can spend nothing at the controller, so energy it draws from the buffer only flows back the way it came. Workers keep the buffer as intake — that is what the buffer is for (ADR 0012) — and source containers stay open to every carrier, so the haul cycle's intake half is unchanged. Unlike ADR 0016's gate, this one discriminates by target kind as well as by body; ADR 0016 deferred exactly that shape ("revisit if…"), and the live loop is the revisit.

## Considered Options

- **Keep the controller container out of the Withdraw pool entirely** — rejected: workers upgrading beside the buffer are its intended consumers; pooling it only as a Refill target strands the energy the haulers deliver.
- **Anti-thrash: forbid a creep the Refill of the container it withdrew from this tick** — rejected: it needs per-creep memory of a *target* (today only the assignment is remembered), and it hides the loop rather than removing it — the same two Tasks would still bid against each other every tick, one creep removed.
- **Demote controller-container Withdraw below every Refill (target layering, ADR 0010 style)** — rejected: rank cannot express it. Whatever tier the Withdraw sits in, it is the empty hauler's only candidate when the source containers are dry, so the cycle survives the demotion; and demoting it for workers revives the commute ADR 0012 killed.
- **Gate on the creep's ability to reach a better sink (spawn/extensions with free capacity)** — rejected: colony-state-dependent applicability, so a Task flickers in and out for one creep as unrelated structures fill; the body gate is decided by geometry and part counts alone.

## Consequences

- `applicable`'s doc comment gains a paragraph naming this ADR. The gate is not a second comparative one (ADR 0016's shape): its body half is a presence test, and what is new is that it reads the target's kind beside the body. The invariant that gates read part counts, never names or roles, stands.
- The Withdraw glossary entry gains a target clause beside its body clause: the buffer is intake for bodies that can spend at the controller.
- A hauler with nothing to draw from now idles (`NoneApplicable`) instead of cycling a container. Idling is the honest state: the colony's sinks are full, and the hauler quota (ADR 0012) is what should shrink.
- The Atlas gains `controllerContainers`, the buffer census by id, memoised per tick beside the Work Areas (ADR 0017's shape) since the gate asks per creep and per candidate. `dualSeats` and it share one `upgradeArea` helper.
- The buffer's geometry is now judged in two places: the Atlas query (Upgrade Work Area ∩ no source Seat) and the Planner's own inline test for Refill layering (Chebyshev range 3 of the controller ∩ not within range 1 of a source). They differ only on tiles no container can stand on — a wall, a source's own tile, an impassable tile — so the pool and the gate agree on every real room. Neither side is uniformly the tighter one — the Atlas is tighter on passability and looser on the source exclusion — and each place they part is unreachable geometry. The duplication is accepted rather than resolved: retiring the Planner's copy means handing `planTasks` the Atlas, which is a wider change than this loop needs. If either side's geometry moves, they must move together.
- Deployment heals the live colony without a death: the kept Withdraw releases as inapplicable on the first tick.
- The test surface (DecideTests): an empty hauler standing beside a stocked buffer takes the far source container instead; with only the buffer stocked it idles with the `NoneApplicable` Verdict. The existing worker-side tests pin that workers still draw from the buffer.
