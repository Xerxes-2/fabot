# Working ground is off-limits to the cluster; the horizon stays at RCL4 plus Storage and Link footings

> **Answered by ADR 0038** on the sentence that deferred it: the order the Link footings fill in, and the links' send/receive behaviour, were left to RCL5, and RCL5's answer is that this room fills none of them — the only prize is a hauler body, and the row is already at its floor of one per source container. The footings stay reserved exactly as this ADR reserved them. **Revised by ADR 0039** on the horizon, which moves to RCL5 — this ADR's reason for holding it at RCL4, ten extensions in the north band and the controller pocket pushing the trunks, was weighed against an ordering that still offered the pocket. It no longer does, and the re-derivation finds the trunks unmoved. The title's "the horizon stays at RCL4" is now history; what this ADR reserved beyond the horizon, the Storage and the Link footings, is unchanged. **Revised again by ADR 0055**, which moves the horizon to RCL6 and rests on this ADR's exclusion rather than amending it: it is the working-ground exclusion that pushes the ten new picks a ring out onto row 34 and column 17 instead of onto a [[seat]] or an Upgrade tile.

> **Revised by ADR 0027** on the Link footings, in three places: the count is one per *planned source container* plus the controller container plus the Storage, not four and not one per Post (a Post needs a standing container, so a Post-anchored rule reserves nothing at level 0); Link is a **built** kind only, never a placeable one, so no placement Intent for a link exists; and the footings' tiles are settled *after* the trunks — only their count is reserved before them, by widening the clustered window.

ADR 0011's one ordering rule — spawn-colour checkerboard, nearest-to-spawn first — excluded nothing but occupied tiles, and said to revisit the RCL4 horizon when RCL4 was in sight. Simulating that rule on W12S28's real terrain at RCL4-in-sight (progress 84k/135k) showed why the revisit matters: the spawn sits in a wall pocket seven tiles from a controller whose Upgrade Work Area is 25 tiles, so the RCL4 extensions already narrow the corridor to the controller container, and an RCL5 reservation (30 extensions, 2 towers) would put extensions on three Upgrade standing tiles (8,40 / 8,42 / 6,38) and on a Seat of the east source (17,39), with the trunks and the controller container rerouting around them. We decided two things. **The clustered ordering excludes the working ground** — every source's Seats and the controller's Upgrade Work Area — as a general rule, not a room exemption: a clustered structure there eats a tile an Anchor or an upgrader stands on, and nothing a tower or extension does is worth that. **The clustered horizon stays at RCL4**; what the Layout reserves beyond it is only the tiles that never come back once an extension takes them: the Storage (one tile, the cluster's first pick, placed the tick RCL4 lands) and four Link footings (one per Post, one beside the controller container, one beside the Storage — the buildable tile within range 1 of its target, off every trunk, nearest the spawn), placed when their level arrives. A Link footing is the one structure allowed on working ground: a link there buys the Anchor and the upgraders a transfer without leaving their tile.

## Considered Options

- **Horizon to RCL5** — rejected for this room's geometry: ten more extensions land in the north band (rows 35–37) where the source→controller trunks already run and in the controller pocket, buying longer trunks for structures a level away. The five reserved tiles are the whole irreversible part of RCL5; the rest can be re-derived when RCL5 is in sight, exactly as ADR 0011 intended for RCL4.
- **Horizon to RCL5 but sites paced** — rejected: ADR 0011 already refused pacing; a stateless planner has nothing to pace with.
- **Excluding a one-tile corridor around the Work Area as well** (to keep 9,39 and 9,41 free) — rejected: "corridor" has no geometric definition that isn't a room-specific exemption; the two-lane bottleneck stays passable through the roads at 9,38 and 9,42, and the first live traffic observation decides whether it needs a rule.
- **Storage on its own placement rule** (a movement-colour tile adjacent to the spawn, or the first pick with three or more open neighbours) — rejected: both are special cases of the kind ADR 0011 exists to avoid. The first pick (14,42) is a two-entrance pocket beside the spawn; accepted as-is, with the hauler's standing tile one step further from the spawn than ideal.
- **Storage as the trunk hub** — rejected: it stands beside the spawn by construction, and switching the hub the tick it is built is a phase change for zero precision.

## Consequences

- Seats and the Upgrade Work Area are read by the Layout before the ordering, so the container picks (ADR 0012) no longer have to dodge reservations on Seats.
- The Layout gains Storage and Link as placeable kinds. Storage is RCL-gated by the engine's allowance; Link footings are reserved from level 0 and placed at the level that allows links, in an order this ADR deliberately leaves to RCL5's design together with the links' send/receive behaviour.
- Storage's Task semantics (Refill tier, Withdraw tier and gating) are ADR 0023's, and are not needed until the 30,000-energy site is built.
- The RCL5 revisit will find the north band still open: this ADR reserves nothing there.
- **The mover reads this set too** (#241). What this decision excluded the clustered ordering from, the Resolver now excludes an idle body from: a creep with no Task heads the first step off the working ground rather than parking on it (ADR 0001's Consequences). The reason is this ADR's own, unchanged — a standing tile an Anchor or an upgrader needs is not worth what stands on it — and only the thing being kept off it is new. The set is not widened to do it: a source container stands on a Seat and the [[buffer]] stands in the Upgrade Work Area, so the stores whose refill tiles the live jam was about are already inside it, while the Storage's and the [[refill cluster]]'s rings are not and stay out. It is narrowed instead, in the one place asking room by room found it too wide: the Upgrade half is the [[home room]]'s controller alone, an [[outpost]]'s being ground nobody upgrades from (ADR 0042), where the whole-room set the Layout only ever asked about home would have walked an idle body out of a 7×7 nothing works in. **The mover has since stopped reading this set** (#268): the two stores held out above came back as their own jam — a [[storage]] against a wall has two standing tiles, and two idle bodies on them shut the hauler holding its [[refill]] out exactly as the pocket did — so the Resolver reads `Atlas.idleGroundIn`, this ADR's set plus the walkable range-1 ring of each store #268 enumerates in the room: the source [[container]]s, the [[buffer]], the [[storage]] and the [[refill cluster]]'s members. A tower's ring is not in it — a tower is a Refill target like the rest (ADR 0010) and jams the same way, so it is a follow-up and not an exemption. This set is unchanged and stays the *Layout's*: what it excludes the ordering from is where work happens, which is a question about placement, and what the mover needs is where standing idle blocks somebody, which is a fact about traffic and strictly wider — widening this one to answer that would move every clustered pick. The narrowing above survives into the wider set, which is built on it.
